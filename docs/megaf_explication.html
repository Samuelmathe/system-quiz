À quoi sert ce programme ?

La carte Arduino Mega est le cerveau du plateau. Elle :

  • reçoit les appuis buzzer des équipes (radio 2,4 GHz) ;
  • allume les projecteurs en couleur DMX ;
  • envoie les événements au PC (BUZZ:3, etc.) ;
  • relaye les sons vers le nano DFPlayer ;
  • reçoit les ordres de l’animateur (valider, refuser, configuration).

Le programme se structure en deux grandes parties :

  • setup() exécuté une fois au démarrage ;
  • loop() répété en permanence (plusieurs milliers de fois par seconde).
Buzz équipe (radio) │ ▼ Mega : fenêtre 50 ms → choix 1 équipe │ ├──► DMX : couleur équipe ├──► PC : "BUZZ:n" (Quiz Board) └──► Nano : son buzz (cmd 200) Animateur VALIDER / FAUX (radio ou PC) │ ├──► Flash vert (99) ou rouge (88) DMX ├──► Son victoire (201) ou échec (202) └──► PC : CMD_SENT:RESET_ALL ou RELANCE_PARTIEL

2. Configuration matérielle

Lignes 9 à 31
RF24 radio(9, 53);
const byte adresseBuzzers[6] = "00001";
const byte adresseSon[6]     = "00002";
#define RADIO_CHANNEL  108
#define LED 13
#define MAGIC_NUMBER 0xAB
#define PC_SERIAL Serial3
  • radio(9, 53) — module nRF24 : broche CE = 9, CSN = 53 sur la Mega.
  • « 00001 » — adresse radio des buzzers et du bouton animateur.
  • « 00002 » — adresse du nano « son » (DFPlayer).
  • Canal 108 — toutes les cartes du projet utilisent le même canal RF.
  • LED 13 — voyant sur la carte (vie du système, réception radio).
  • MAGIC_NUMBER — signature pour vérifier que l’EEPROM contient une config valide.
  • PC_SERIAL = Serial3 — liaison PC via adaptateur USB-TTL sur TX3/RX3 (broches 14/15), 9600 bauds. Le port USB natif reste libre pour le shield DMX.

3. Structure de configuration (EEPROM)

Lignes 33 à 43
struct QuizConfig {
    byte magic;
    int nbEquipes;
    int nbCanaux;
    int offDim, offR, offG, offB;
    int adressesDMX[30];
    byte couleurs[30][30][3];
} settings;

La variable globale settings contient toute la configuration du plateau :

  • nbEquipes — combien d’équipes participent (1 à 30).
  • nbCanaux / offDim, offR, offG, offB — comment est câblé chaque projecteur DMX (quel canal = rouge, vert, bleu, intensité).
  • adressesDMX[30] — adresse de départ DMX de chaque projecteur (0 = désactivé).
  • couleurs[équipe][projecteur][RGB] — quelle couleur afficher quand une équipe buzze.

Au démarrage, cette structure est lue depuis l’EEPROM ; le logiciel de config ou SAVE_CONFIG permet de la modifier puis de la sauvegarder.

5. Protocole radio & anti-doublon

Lignes 55 à 76
struct RadioMsg {
    uint8_t kind;   // 1 = buzz équipe, 2 = commande animateur
    uint8_t value;  // numéro équipe 1..30 ou code 88 / 99
    uint16_t seq;   // numéro de séquence
};

static void radioSendCmdToBuzzers(uint8_t value) {
    RadioMsg msg = {2, value, ++seqOutboundCmd};
    radio.stopListening();
    radio.openWritingPipe(adresseBuzzers);
    radio.write(&msg, sizeof(msg));
    radio.startListening();
}

Chaque paquet radio contient un type, une valeur et un numéro de séquence (seq) :

kindvalueSignification
11 … 30Buzz de l’équipe N
299Bonne réponse (animateur) → reset complet
288Mauvaise réponse → relance partielle

La Mega mémorise la dernière seq par équipe pour ignorer les doublons (même bouton appuyé deux fois, rebond radio). La fonction radioSendCmdToBuzzers permet à la Mega de renvoyer 88 ou 99 aux buzzers quand le PC valide ou refuse.

6. LED & buffer série PC

Lignes 78 à 100
// LED non bloquante
void ledPulse(unsigned long ms) { ... }
void ledUpdate() { ... }

// Buffer ligne série PC
char serialBuf[SERIAL_BUF_LEN];
uint8_t serialLen = 0;

LED non bloquante — au lieu d’utiliser delay() (qui fige tout le programme), la Mega note « éteindre la LED à telle milliseconde » et vérifie dans loop(). Le jeu reste réactif pendant les flashs.

Buffer série — les caractères arrivant du PC sont stockés jusqu’au retour à la ligne (\n), puis la ligne complète est passée à parseCommande(). Pas de classe String Arduino (évite les plantages mémoire).

7. Clignotement DMX (validation / refus)

Lignes 102 à 148
void flashDmxStartVert()  { flashDmxMode = 1; ... }
void flashDmxStartRouge() { flashDmxMode = 2; ... }
void flashDmxUpdate()     { /* 6 étapes × 150 ms : couleur / noir */ }

Quand l’animateur valide ou refuse (ou le PC envoie RESET_ALL / RELANCE_PARTIEL), tous les projecteurs configurés clignotent :

  • Vert — bonne réponse (3 cycles rapides).
  • Rouge — mauvaise réponse.

flashDmxUpdate() est appelée à chaque tour de loop() : progression par petits pas de 150 ms, sans bloquer la radio ni le port série.

8. Gestion des buzz quasi simultanés

Lignes 150 à 156 (+ traitement lignes 326 à 346)
#define FENETRE_MS   50
#define MAX_BUFFER    8
int  bufferSignaux[MAX_BUFFER];
bool fenetreActive = false;
unsigned long debutFenetre = 0;

Si deux équipes appuient presque en même temps, la Mega ouvre une fenêtre de 50 ms : tous les buzz reçus dans cet intervalle sont collectés dans un buffer. À la fin des 50 ms, la Mega retient la première équipe valide du buffer (non déjà jouée, jeu non verrouillé).

Cela évite les litiges « qui a appuyé en premier » tout en restant équitable et déterministe.

9. Configuration usine (par défaut)

Lignes 158 à 210 — fonction initialiserConfigParDefaut()

Si l’EEPROM est vide ou corrompue, ou sur commande RESET_V1, la Mega recharge :

  • 8 équipes, 8 canaux DMX, patch dimmer/R/G/B aux offsets 0–3 ;
  • projecteurs aux adresses DMX 51 et 59 ;
  • palette de couleurs (rouge, bleu, vert, jaune, rose, cyan, …) ;
  • écriture complète en EEPROM avec le magic 0xAB.

C’est la configuration « sortie d’usine » du projet, modifiable ensuite via l’outil de config ou le Quiz Board.

11. setup() — Démarrage (une seule fois)

Lignes 264 à 316

Au branchement ou reset de la carte, setup() enchaîne :

  1. DMX — init contrôleur, projecteurs éteints.
  2. EEPROM — lecture de settings ; si invalide → config usine.
  3. Série PC — ouverture Serial3 à 9600 bauds.
  4. Radio — canal 108, 250 kbps, CRC, accusés de réception, écoute sur « 00001 ». Trois clignotements LED = OK ; LED fixe 2 s = échec.
  5. Purge — vide le buffer radio des paquets parasites.

Après setup(), seule loop() tourne en continu.

12. loop() — Cœur du programme

Lignes 321 à 479

À chaque passage, loop() exécute dans l’ordre :

A. Tâches de fond

  • ledUpdate() et flashDmxUpdate() — fin des flashs LED/DMX programmés.
  • Battement LED toutes les 2 s si radio OK.

B. Fin de fenêtre 50 ms (buzz simultanés)

Si la fenêtre est expirée : choix de l’équipe gagnante → verrouillage → couleur DMX → BUZZ:n vers PC → envoyerSon(200, n).

C. Port série PC

Lit les caractères sans bloquer ; à chaque ligne complète → parseCommande().

D. Réception radio

  • Buzz équipe (kind=1) — ajout au buffer de la fenêtre 50 ms.
  • Commande 99 — bonne réponse : PC notifié, son 201, flash vert, déverrouillage, reset dejaJoue.
  • Commande 88 — mauvaise réponse : PC notifié, son 202, flash rouge, déverrouillage (équipe peut rebuzzer).

Chaque paquet passe d’abord par le filtre anti-doublon (seq).

14. Fonctions lumières DMX

Lignes 618 à 664
void setProjecteur(int addr, int r, int g, int b);
void eteindreLumieres();
void allumerCouleurEquipe(int equipe);
  • setProjecteur — écrit dimmer à 255 puis R, G, B aux offsets définis dans settings, à partir de l’adresse DMX addr.
  • eteindreLumieres — met à 0 tous les canaux de tous les projecteurs configurés (adresse 1–512).
  • allumerCouleurEquipe — éteint tout, puis pour chaque projecteur applique la couleur mémorisée pour l’équipe qui vient de buzzer.

C’est l’effet visuel en salle : une équipe buzze → ses projecteurs s’allument dans sa couleur.

15. Résumé — cycle d’une question

Vue d’ensemble client
  1. Attente — jeuVerrouille = false, projecteurs éteints (ou état précédent).
  2. Buzz — radio reçoit kind=1 → fenêtre 50 ms → une équipe retenue.
  3. Action buzz — DMX couleur + BUZZ:n PC + son 200.
  4. Verrou — jeuVerrouille = true : plus d’autre buzz accepté.
  5. Validation animateur / PC — 99 ou RESET_ALL → flash vert, reset manche.
  6. Refus — 88 ou RELANCE_PARTIEL → flash rouge, déverrouillage, autres équipes peuvent rebuzzer.

Le firmware est entièrement non bloquant : radio, DMX, PC et flashs coexistent grâce à millis() et à des mises à jour par petits morceaux dans loop().
